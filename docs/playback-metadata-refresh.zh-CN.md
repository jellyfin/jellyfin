# 将播放探测与描述性元数据刷新隔离

[English](playback-metadata-refresh.md)

状态（2026-10-19）：已在 `codex/upstream-playback-metadata` 实现并测试，直接基于官方 `master` 提交 `08c2ba6e0b6499122822f1c5b18bc426104538b4`。本文是供审核的工程参考资料，不是已经提交的 PR 正文。尚未创建上游 PR。所有验证均使用隔离夹具，没有使用或更改已安装的服务器和真实媒体库。

## 使用流程与实际问题

我们的日常流程是先从 NFO 导入媒体库，再用外部工具调用 Jellyfin 编辑 API，将流派和地区翻译、整理。数据库保存修改后的值，源 NFO 则可能仍保留旧值。之后请求播放信息时，旧描述可能被重新导入；用户并没有要求刷新这些描述。

原始媒体库使用符号链接和定制的极速导入模式，暂缓读取视频技术信息。本补丁不依赖该定制。下面的复现使用官方已有的 STRM 路径和通过 HTTP 提供的生成视频，不使用插件或自定义导入选项。

在上游 `MediaSourceManager.GetPlaybackMediaSources` 中，允许探测、媒体源不是占位条目，且条目是 STRM 或缺少主音视频流时，会进入 `FullRefresh`。这是普通元数据流程，NFO、本地和远程描述提供者以及内嵌标签都可能参与。NFO `lockdata`、数据库 `LockedFields` 和合并规则决定最终结果。仅设置 `ReplaceAllMetadata=false` 无法保证描述不被修改。

## 修改前后的实际复现

两个构建使用同一官方基线和同一夹具脚本。每次运行新建临时服务器、数据库和相同的生成媒体／NFO 输入，使用随机私有凭据和回环端口。关闭 NFO 保存、计划任务触发器、实时监控、远程元数据和图片抓取器；等待初始扫描完成后再编辑。

脚本先导入 NFO，再提交完整 DTO，通过 API 修改描述并保持**没有字段锁**，回读确认保存。随后两次 POST 请求 PlaybackInfo，每次都回读元数据。基线和补丁服务器都返回可用的 160×90 视频流，源 NFO 字节保持不变。

| 场景 | 未修改的官方版本：播放后 | 核心补丁：两次播放请求后 |
| --- | --- | --- |
| NFO `lockdata=true`；API 流派为 `剧情`、地区为 `中国` | 流派变成 `Original genre`；地区变成 `Original country, 中国`；标题／简介回退到 NFO，整项锁变成 true | API 流派、地区、标题、简介和锁状态均保持不变 |
| NFO `lockdata=false`；相同 API 修改 | 流派保持修改值，但地区追加了 `Original country` | 所有修改值均保持不变 |
| NFO `lockdata=true`；API 主动清空流派、地区和简介 | 空字段被旧 NFO 值重新填充 | 空值保持为空 |

第一行包含替换和集合合并，不代表每种 NFO 配置都会替换每个字段。未锁定 NFO 用例展示了同一个错误播放刷新入口下的另一种合并结果。

实际 API 观察记录已脱敏保存：[修改前](evidence/playback-before.json)、[修改后](evidence/playback-after.json)。补丁运行还临时让生成视频返回 HTTP 404，确认已有音视频流、时长和描述仍然可用。恢复视频后主动执行替换全部元数据，仍能从 NFO 导入原始流派，证明普通刷新功能保留。

## 实现边界

1. 播放传递 `RefreshMediaInfoOnly=true` 并禁用图片刷新。保留官方当前探测触发条件，包括 STRM 重复探测。
2. `BaseItem.RefreshMetadata` 在此范围跳过附属条目和图片维护。`MetadataService` 只执行实现 `IMediaInfoProvider` 的自定义提供者，`ProbeProvider` 实现该约定。跳过 NFO／远程描述、普通刷新前后钩子、图片提供者和描述刷新时间更新，首次刷新、整项锁定时也适用。
3. 跳过视频内嵌描述和人员写入，跳过音频标签描述写入。仍处理音视频流、已有外部字幕／音轨、附件和章节等技术数据；播放不发起字幕下载或章节图片提取。缺少所需主流的探测结果会在替换技术数据前被拒绝。
4. `ItemUpdateType.MediaInfo` 选择限定字段的条目保存。`SaveMediaInfoAsync` 在事务中读取当前数据库行，只更新时长、码率、大小、宽高和明确列出的技术 JSON 属性。保留当前描述、字段锁、刷新时间、其他 JSON 属性和版本关系。跳过完整条目保存、NFO 保存器、图片保存和版本重建；保存后使条目缓存失效。
5. `Video.UpdateToRepositoryAsync` 对该更新类型不再向副版本复制描述。否则即使排除 NFO 提供者，探测主版本仍可能覆盖副版本独立编辑的描述。
6. 提供者执行失败或取消时，恢复缓存条目原来的技术标量／数组属性，不进行限定条目保存。提供者报告没有可用更新时也恢复这些状态。

必要的保存边界和副版本保护与入口修复一起提交。本分支不包含独立的集合合并修复、NFO 原子保存、极速导入／Moonfin 定制、翻译工具、新重置接口、版本号或技术流复用策略。

现有 HTTP 请求／响应结构和编辑 API 保持兼容，用户主动刷新和替换全部元数据的行为不变，不增加数据库迁移。服务端提供者和持久化接口增加了技术范围约定，自定义实现需要支持；自定义技术提供者必须遵守该范围，不进行描述性写入。

### 明确保留的边界

本补丁阻止播放探测改写描述性元数据，不处理多个显式编辑请求之间或旧完整 DTO 提交的冲突，也不把音视频流、附件、章节和条目写入变成统一的崩溃原子事务：现有技术仓储仍分别保存。网络／探测失败和取消测试不能被解释为已证明任意数据库失败或进程崩溃后都能完整回滚。这些能力仍是独立提案。

同样保留原有探测选择规则。减少 STRM 重复探测、按版本选择缺失流，以及源变化／重新验证策略应另行评审。真实 HTTP 复现覆盖电影；音频、缺少主流的判断和副版本描述边界由自动化组件测试覆盖。这是 PlaybackInfo 验证，不是 GUI 播放器或转码端到端验收。

## 复现与验证

夹具只接受服务器 DLL 和 ffmpeg 可执行文件，不接受已有服务器地址或凭据。媒体库、生成视频、配置、缓存和数据库均位于新建临时目录，只停止自己启动的子服务器，保留报告供检查。

先将未修改的官方基线构建到独立输出目录，再把补丁构建到另一目录。在包含夹具的工作区运行：

```sh
python3 tests/fixtures/playback_metadata.py \
  --server-dll /absolute/baseline/jellyfin.dll \
  --ffmpeg /absolute/bin/ffmpeg --expect-overwrite

python3 tests/fixtures/playback_metadata.py \
  --server-dll /absolute/patched/jellyfin.dll \
  --ffmpeg /absolute/bin/ffmpeg
```

`--expect-overwrite` 断言基线确实出现已识别的覆盖。也已在未修改基线上运行普通保护断言，确认锁定 NFO 用例以退出码 1 失败，补丁构建以退出码 0 通过。没有该开关时，任何整理后描述／锁状态的改变都会导致测试失败。补丁运行还检查源暂时不可用和主动替换全部元数据。没有通过修改 SQLite 来制造 HTTP 失败。

验证环境：macOS arm64，.NET SDK 10.0.301，Release 配置。
